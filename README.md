## 기록 규칙

발주·납품은 [공동 양식](docs/발주-납품-양식.md)을 사용한다. 영상은 채널에 첨부하고 저장소에는 파일명·크기·SHA-256·실행 ID·납품 메시지 링크를 기록한다. 코호는 전달받은 원본을 로컬에 보관하며, 별도 요청 없이 MP4를 Git에 커밋하지 않는다.

1. **회의 끝날 때 회의록 한 장** — `meetings/YYYY-MM-DD-주제.md`. 세 칸만 채운다: `결정한 것` / `제안 중인 것` / `누가 무엇을 할지`. 중요한 결정에는 원 대화 링크. 길게 쓰지 않는다.
2. **정해진 건 즉시 결정 기록으로** — `docs/결정과-승인.md` 표에 한 줄 추가. 누가 정했는지, 크레딧이 얼마인지, 원 대화 링크까지 같이 적는다. 회의록에만 남기고 끝내지 않는다. 위임받아 만든 산출물은 결정이 아니라 `위임`으로 적는다.
3. **기획안은 최신본 하나만** — 고칠 때 새 파일(v6, v7)을 만들지 않고 `docs/jeonghee_pilot_기획안_v5.md`를 그대로 수정한다. 이력은 git이 갖는다.
4. **커밋은 한 건에 하나** — `회의: 11-05 정희 3차` / `문서: 03-A 소매 문구 수정` 처럼 앞에 종류를 붙인다.
5. **크레딧 실행은 전후 한 줄씩** — 실행 전 견적을 `결정과-승인.md`의 승인 대기 표에, 실행 후 실제 차감과 버전·시도·실행 조건·검수 판정을 `숏별-제작기록.md`에. 같은 숏을 다시 뽑으면 버전을 올린다.
